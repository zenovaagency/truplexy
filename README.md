# Truplexy — marketing site

**One conversation. Everywhere.** The homepage positions Truplexy as a continuous AI
customer-support layer across channels, not a single website chatbot.

Astro 7 + React islands + Tailwind v4, with GSAP/Lenis for motion. Structure mirrors `zenova-v2`.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server on http://localhost:4321 |
| `npm run build` | Static build to `dist/` |
| `npm run check` | Type-check (`astro check`) |
| `npm run verify` | Honesty audit of the built home, `/channels/*` and `/docs/*` pages (run after build) |
| `npm run brand` | Regenerate trimmed logos, favicons and the OG card from `/logo` |

## Deploying

`vercel.json` deploys this site and the dashboard (`dashboard/`) as one Vercel project with two
services: `dashboard` on `app.` hosts (`app.truplexy.com`), `site` on every other host.
`vercel dev` runs both locally (the dashboard at `http://app.localhost:3000`).

## Search (SEO)

- `/robots.txt` is generated by `src/pages/robots.txt.ts` and points at `/sitemap-index.xml`, which
  `@astrojs/sitemap` builds from every page except the 404. Each sitemap `lastmod` is the last commit
  touching that page's sources (`PAGE_SOURCES` in `astro.config.mjs`). It is left out when the build
  runs from a shallow clone, because every file would then show the same date. Add new pages to
  `PAGE_SOURCES` if they read from more than their own file.
- URLs have no trailing slash (`trailingSlash: 'never'`). `vercel.json` sends a 308 from `/page/` to
  `/page`, and from `www.` to the apex domain.
- `src/layouts/Base.astro` sets the canonical URL, robots meta, Open Graph/Twitter tags and JSON-LD
  (`Organization`, `WebSite`, `SoftwareApplication`, plus `BreadcrumbList` when a page passes
  `breadcrumbs`). Pass `noindex` to keep a page out of search.
- Google Search Console: verify the domain by DNS, or set `PUBLIC_GOOGLE_SITE_VERIFICATION` in the
  build environment to render the verification meta tag. Then submit
  `https://truplexy.com/sitemap-index.xml`.
- The dashboard (`app.`) is kept out of search with an `X-Robots-Tag: noindex` header
  (`vercel.json`) and a noindex meta. Its `robots.txt` still allows crawling, so crawlers can see that.

## Where things live

- `src/data/channels.ts` — **channel registry**. Every badge, diagram node and footer
  list reads `status` from here. Flip a channel to `'live'` and the whole page follows.
- `src/data/demo.ts` — every sample conversation, from one fictional cast. The build
  fails if a demo uses a channel that isn't live.
- `src/data/site.ts` — name, domain, email and CTA links.
- `src/components/home/*` — one file per homepage section, in page order in `src/pages/index.astro`.
- `src/islands/*` — the interactive parts: the hero card stack (sample conversation playback) and the unified inbox.

## Website SDK

`sdk/` holds the website chat SDK: the `<truplexy-chat>` widget (`@truplexy/web`), React and Vue wrappers, the server route (`@truplexy/server`) and a WordPress plugin. It is its own npm workspace. Run `cd sdk && npm install && npm test`, and see `sdk/README.md`. The typed server client and contact-based identity flow are documented in `sdk/CHAT_API.md`; `API_REFERENCE.md` is the API contract.

## Channel pages and docs

Every channel in `src/data/channels.ts` gets two pages, both on the docs layout (`src/layouts/Docs.astro` + `src/styles/docs.css`: hero, sticky "On this page" list, `.docs` article):

- `/channels/<id>` (`src/pages/channels/[id].astro`): what Truplexy does there, how it works, plans, FAQ. `/channels` lists them all.
- `/docs/<id>` (`src/pages/docs/[id].astro`): the setup guide, with server code per language. `/docs` lists them all. Website chat keeps its own, longer guide at `/docs/web-sdk`.

Adding a channel: add it to the registry, then add its entry to `GUIDES` in `src/data/channel-guides.ts` (`npm run check` fails on a missing one). Plan availability is read from `COMPARISON` in `src/data/pricing.ts` by `planLabel`. The server code is not written here: `src/data/snippets.ts` arranges the dashboard's snippet packs (`dashboard/src/features/integrations/snippets/`) into tabs, so the dashboard guides and these pages share one source. The provider-side steps in `channel-guides.ts` extend `dashboard/src/features/integrations/catalog.tsx`; update both when a platform's setup changes. Those snippet files must stay free of dashboard-only imports (`@/…`), since the site imports them.

Its install guide is `src/pages/docs/web-sdk.astro` (`/docs/web-sdk`). That page reads the framework recipes from `dashboard/src/features/integrations/snippets/web-sdk.ts`, the same file the dashboard's Website chat guide uses. Its live demo widget is built from `sdk/packages/web/src`.

## Before launch

Search for `PLACEHOLDER`:

- `src/data/site.ts` — contact email, sign-up URL and demo-booking URL (currently
  `mailto:` links). The domain (`url`) set there feeds `astro.config.mjs` (`site`), canonical URLs,
  `robots.txt` and the sitemap.
- `src/components/home/Context.astro` — the one-line privacy note under "No unnecessary
  repetition". Confirm it matches how Truplexy actually handles conversation data.
